移動中や打ち合わせの直後に、スマホへ「来週火曜の14時から青嵐精機さんと打ち合わせ」と話しておく。あとで見返すと「晴嵐正規さん」になっていて、予定表にも入っていない。音声メモが仕事で使いにくい理由は、ほぼこの 2 つです。**取引先の名前が化けること**と、**文字になっても予定やタスクに変わらないこと**。

そこで、話したメモを AmiVoice API で文字にして、曜日・時刻・金額・取引先を取り出し、Markdown のメモとカレンダー用の `.ics` まで作る小さな CLI をつくりました。

| 実測したこと（合成音声 6 文） | 値 |
|---|---|
| 取引先名の正解（単語登録なし → あり） | 3/6 → **6/6** |
| 文字誤り率 CER（なし → あり） | 3.2% → **0.0%** |
| ノイズ SNR 10 dB での期待語（なし → あり） | 17/22 → **20/22** |
| 1 文あたりの文字起こし時間 | 約 1.4 秒 |
| 構造化の正解項目（ルール／ローカル LLM 120B） | **19/19**／17/19 |

リポジトリ: https://github.com/Wisteria-Corp/voicememo-amivoice （MIT）

## できること

```bash
python voicememo.py run --words words.txt
```

Enter で録音を止めると、次の 3 ファイルが `memo/` にできます。

```markdown
# 来週火曜の14時から青嵐精機さんと打ち合わせです

- 基準日: 2026-11-07／文字起こし 1.43s

## 予定
- 2026-11-10 14:00 — 来週火曜の14時から青嵐精機さんと打ち合わせです

## 抽出
- 固有名詞: 青嵐精機
```

- `.md` … メモアプリにそのまま置けるメモ
- `.json` … 抽出結果（日付・時刻・金額・ページ数・取引先・TODO）
- `.ics` … 予定があるときだけ。カレンダーにドラッグすれば登録できます

処理は 3 段です。

```
録音（16kHz mono WAV）
  → AmiVoice API（同期 HTTP・汎用エンジン・単語登録つき）
  → 構造化（曜日を基準日から計算・金額/時刻/取引先を抽出）
  → .md / .json / .ics
```

## なぜ AmiVoice か — 取引先名は「登録すれば当たる」

前回の記事で、同じ合成音声 6 文を 23 の条件で文字起こしして比べました（[日本語 STT 12 エンジン実測](https://zenn.dev/wisteriacorp/articles/wisteria-2abed5b30bd1)）。上位はこうです。

| エンジン（条件） | CER | 固有名詞 | 応答/文 |
|---|---|---|---|
| **AmiVoice 汎用＋単語登録 3 語（表記＋読み）** | **0.0%** | **6/6** | 1.4 秒 |
| Google Chirp 3＋適応フレーズ 3 語 | 0.0% | 6/6 | 3.1 秒 |
| Deepgram Nova-3＋keyterm 3 語 | 0.8% | 6/6 | 1.1 秒 |
| OpenAI gpt-4o-transcribe＋prompt 3 語 | 1.4% | 6/6 | 1.3 秒 |
| AmiVoice 汎用（登録なし） | 3.2% | 3/6 | 1.1 秒 |

登録なしの AmiVoice は、こう間違えます。

| 話した文 | 登録なし | 登録あり |
|---|---|---|
| 青嵐精機さんと打ち合わせです | **晴嵐正規**さんと打ち合わせです | 青嵐精機さんと打ち合わせです |
| KTSラボから金曜に請求書が届く予定です | **KBSラボ**から金曜に請求書が届く予定です | KTSラボから金曜に請求書が届く予定です |

音としては正しく聞き取れていて、漢字の当て方とアルファベット 1 文字だけが違います。こういう誤りは**辞書で直せる種類の誤り**です。AmiVoice の単語登録は「表記」と「読み」を組で渡せるので、「せいらんせいき」と聞こえたら必ず「青嵐精機」と書く、という指定ができます。上位のほかの 3 つは、今回の条件では「この語を優先して」と語だけを渡す方式で、読みは渡していません。仕事のメモで化けるのはほぼ取引先名なので、読みつきで確定できる点を決め手にしました。

## 工夫 1: 単語辞書を取引先一覧から自動生成する

単語登録は効きますが、手で書くと続きません。取引先は増えますし、登録し忘れた名前ほど化けます。そこで、**すでにある取引先一覧の CSV から辞書を作る**ことにしました。

```bash
python words_from_csv.py customers.csv --name-col 社名 --yomi-col 読み > words.txt
```

```text
# 表記 読み（ひらがな）。すべて架空の固有名詞
青嵐精機 せいらんせいき
ノルディックベーカリー のるでぃっくべーかりー
KTSラボ けーてぃーえすらぼ
```

やっていることは 3 つです。

1. **法人格を外す**。「株式会社青嵐精機」ではなく「青嵐精機」で登録します。話すときは法人格を付けないので、話す形に合わせます
2. **読みの列があれば使い、なければ仮の読みを付けて `# 要確認` を付ける**（`pykakasi` があれば）。社名の読みは機械では当たらないことが多いので、黙って採用しません
3. **1 行「表記 読み」で出す**。`voicememo.py --words` がそのまま読みます

顧客管理や会計のソフトから取引先を CSV で書き出せる職場なら、月 1 回この 1 行を回すだけで辞書が追いつきます。単語登録を「設定」ではなく「運用」に組み込む、というのがこの CLI でいちばん伝えたいことです。

## 工夫 2: 曜日は LLM に任せず計算する

文字になったメモから予定を作るには、「来週火曜」を日付に直す必要があります。ここは**正規表現と小さな暦ロジック**でやっています。

```python
def resolve_weekday(base: dt.date, word: str, modifier: str | None) -> dt.date:
    """『来週火曜』『今週金曜』『火曜』を日付にする。週は月曜始まり。修飾なしは「次に来るその曜日（今日を含む）」。"""
    target = WEEKDAYS.index(word)
    monday = base - dt.timedelta(days=base.weekday())
    if modifier == "今週":
        return monday + dt.timedelta(days=target)
    if modifier == "来週":
        return monday + dt.timedelta(days=7 + target)
    if modifier == "再来週":
        return monday + dt.timedelta(days=14 + target)
    delta = (target - base.weekday()) % 7
    return base + dt.timedelta(days=delta)
```

「生成 AI に JSON で返させれば一発では？」と思ったので、比べました。同じ 6 文・基準日 2026-11-07（土）で、日付・時刻・金額・取引先の 19 項目を採点しています。LLM はローカル GPU マシンの Ollama で、temperature 0・JSON 出力指定です。プロンプトには基準日と「週は月曜始まり」を渡しました（`samples/compare_llm.py` で再現できます）。

| 方式 | 正解項目 | 誤った日付 | JSON 失敗 | 1 文あたり |
|---|---|---|---|---|
| **ルール抽出** | **19/19** | **0** | 0 | 0.00 秒 |
| gpt-oss:120b | 17/19 | 2 | 0 | 24.8 秒 |
| qwen3.8:27b | 15/19 | 1 | 1（300 秒でタイムアウト） | 98.2 秒 |
| qwen3-vl:8b-instruct | 4/19 | 3 | 0 | 5.3 秒 |

数字より、外し方のほうが問題でした。

- 120B は「月曜と水曜は KTS ラボの定例です」を、**先週の**月曜と水曜にしました。JSON としては正しく、日付の形式も正しいので、目で見ないと気づきません
- 8B は、文に無い「10:00」を補って予定にしました。予定表に存在しない会議が入ります

逆にルール側も最初は 18/19 で、「月曜と水曜」の 2 つ目を落としていました。1 文に日付が 2 つあると先頭だけ使う実装だったためで、「と・、や」で並列につながる日付は全部使うように直しました。「日曜の午前九時に土曜の分のログを」のように並列でないものは先頭だけです。テストに 2 件足しています。

結論として、**日付・時刻・金額はルールで確定し、LLM は使うとしても要約や言い換えだけ**、という分担にしています。LLM は `--llm` を付けたときだけ呼ばれる任意の口です。

## 使ってみた — ノイズと早口で単語登録は効くか

自分の声は公開したくないので、合成音声にノイズと速度変化を加えて測りました（`samples/robustness.py`）。期待語は 6 文で 22 個です。

| 条件 | 登録なし | 登録あり |
|---|---|---|
| そのまま | 19/22 | **22/22** |
| ノイズ SNR 20 dB | 18/22 | **22/22** |
| ノイズ SNR 10 dB | 17/22 | 20/22 |
| 1.15 倍速 | 20/22 | **22/22** |

SNR 10 dB で初めて登録ありでも取りこぼしが出ますが、どの条件でも登録なしより 2〜3 語多く当たっています。単語登録は、静かな環境でだけ効く飾りではありませんでした。

## ハマりどころ

1. **`profileWords` は URL エンコード必須**です。エンコードしないとエラーにならず、**黙って無視されます**。「登録したのに効かない」の正体はたいていこれです

```python
d = f"grammarFileNames={engine}"
if words:
    pw = "|".join(f"{w} {y}".strip() for w, y in words)
    d += " profileWords=" + quote(pw, safe="")  # ← これを忘れると黙って無視される
```

2. **ログ保存なし（`loggingOptOut=True`）は、私の契約では「認証不正」**になりました。エラー文がキーの誤りに見えるので、キーを疑って時間を使いました
3. **API キーはマイページ「接続情報 → 共通接続情報」の長い方**です。8 桁のサービス ID を入れても動きません。環境変数に入れるときは末尾の改行にも注意してください（コードでは `.strip()` しています）

## 限界と次にやること

- **品番・伝票番号のような定型の英数字**は、単語登録では追いつきません。AmiVoice にはルールグラマという仕組みがありますが、使えるのは専用環境の API か SDK で、共用 API の範囲では辞書で補うしかありません
- **同期 HTTP なので、話し終わってから文字になります**。WebSocket のストリーミング認識に替えれば、話しながら確定できるはずです
- **話者は分けていません**。打ち合わせの録音ではなく、1 人で話すメモが前提です
- 辞書は毎回リクエストに載せています。登録語が数百を超えるなら、マイページ側の単語登録に移すほうが素直です

## 試し方

```bash
git clone https://github.com/Wisteria-Corp/voicememo-amivoice
cd voicememo-amivoice
pip install -r requirements.txt
export AMIVOICE_APPKEY=...   # 無料枠は毎月 60 分
python voicememo.py run --wav samples/s1.wav --words samples/words.txt --base 2026-11-07
python -m pytest -q          # 7 件
```

同梱の音声は合成で、固有名詞はすべて架空です。
